# FLEXG PAGE — 페이지 빌더 데이터 바인딩 영역 화면설계

페이지 빌더 에디터에서 **오른쪽 패널의 [데이터] 탭**을 다시 구성하는 기획 문서 프로토타입.
편집기 화면을 실제로 눌러 보면서, 각 영역의 기능 정의·규칙·예외 케이스를 옆에서 함께 읽는다.

> 작성 : 컨버전스 김하은 / 2026.09.09

## 무엇을 다루나

작업 창에서 고른 자리에 어떤 데이터를 이을지 정하는 영역을, **① 선택 요소 → ② 데이터 설정** 두 단계로 나눠 다시 구성한다.
헤더·왼쪽 레일·왼쪽 패널·캔버스는 지금 쓰는 기본 세팅값 그대로 옮겨 두고, 설계 대상은 [데이터] 탭 한 곳이다.

| 개선안이 지적한 것 | 이 프로토타입에서 정한 것 |
| --- | --- |
| 무엇부터 정해야 하는지 순서가 없음 | ① 선택 요소 → ② 데이터 설정에 번호를 매기고, 요소를 고르기 전에는 ② 단계를 열지 않음 |
| 데이터 소스의 계층이 흐림 | 고른 요소의 성격(그룹 / 낱개)에 맞는 쪽만 열고, 나머지는 잠근 뒤 이유를 칸 아래 한 줄로 알림 |
| 필수와 선택이 섞여 있음 | 반복 데이터와 표시 조건을 **선택 사항**으로 두고, 고르지 않으면 관련 영역 자체를 띄우지 않음 |
| 「바인딩 가능한 속성이 없습니다」 같은 부정 문구 | 무엇을 고르면 되는지 알려 주는 유도 문구로 바꾸고, 점선 상자로 자리를 표시 |
| 이미 만든 기능을 크게 흔들지 않을 것 | 동작은 그대로 두고 순서·잠금·문구·조건 위치만 조정 |

**설계 범위는 오른쪽 패널의 [데이터] 탭 한 영역**이고, 같은 자리를 나눠 쓰는 [스타일]·[애니메이션] 탭은 현행 유지다.

## 실행

```bash
npm install
npm run dev        # http://localhost:3000
```

| 열어볼 곳 | 무엇 |
| --- | --- |

## 정리한 판단

시안에 없거나 어긋나던 부분은 이렇게 정해서 문서와 화면에 반영했다.

| 항목 | 정한 것 |
| --- | --- |
| 단계 순서 | 요소를 고르기 전에는 ② 데이터 설정을 열지 않음. 성격에 따라 고를 수 있는 데이터가 달라 순서를 지키게 함 |
| 반복과 개별 중 한쪽 잠금 | 그룹을 고르면 개별 데이터를, 낱개 요소를 고르면 반복 데이터를 잠금. 잠긴 칸은 눌리지 않고 왜 못 고르는지 한 줄로 알림 |
| 요소를 바꿨을 때 | 고른 값과 걸어 둔 반복을 함께 풀어, 잠긴 칸에 값이 남지 않게 함 |
| 고른 요소 표시 | 목록 안 체크와 색으로만 표시. 위에 한 번 더 보여 주면 같은 것이 두 번 나와 헷갈림 |
| 표시 조건 위치 | 탭으로 가르지 않고 반복 데이터·개별 데이터 각각의 아래에 붙임. 어느 데이터에 건 조건인지 헷갈리지 않게 |
| 조건을 짜는 자리 | 패널이 좁아 팝업으로 뺌. 새로 걸기와 고치기가 같은 팝업을 열고, 적용을 눌러야 반영됨 |
| 조건이 걸렸을 때 | 조건 문장과 함께 지금 데이터로 몇 개에서 보이는지를 숫자로 알림 |
| 적용 시점 | 고르기만 하면 미리보기까지, 적용을 눌러야 캔버스에 반영 |
| 단일 요소 바인딩 테스트 | 반복 부모가 없는 낱개 자리를 점선 상자로 따로 둠. 반복 없이 개별 연결만 확인하는 자리 |
| 화면 위 번호 마커 | 편집기라 요소가 촘촘해 번호가 화면을 덮음 → 끄고 설명 패널 번호만 씀 |
| 요소를 고르는 길 | 캔버스 · 레이어 · 요소 목록 세 곳 어디서 골라도 결과가 같게 함 |
| PAGE 서비스 색 | 디자인시스템에 PAGE 컴포넌트도 토큰도 아직 없어, 색을 화면 파일 맨 위 한곳에 모으고 문서에 「디자인시스템 요청 대상」으로 표시 |

> 상태는 **작성중**. 개선안과 대조해 남은 것 — 그룹에 반복을 건 뒤 안의 요소를 고르면 반복이 풀리는 점, 같은 성격의 요소가 함께 골라지는 점, 반환값 미리보기가 고른 항목을 따라가지 않는 점, 개선안 4단계 중 포맷팅이 아직 없는 점.

```
    pageBuilderData.ts  화면 문구·요소 목록·레이어·아트보드·필드·조건 데이터

```

## 작업 규칙

- 화면은 `src/design-system` 배럴의 표준 컴포넌트로 조립한다. **PAGE 서비스는 아직 표준 컴포넌트가 없어 이 화면은 전부 임시 조립**이고, 설명에 「디자인시스템 요청 대상」으로 남겨 뒀다.
- 설명(`body`)은 기능 정의·규칙·예외 케이스로 쓴다. 컴포넌트명·색·px는 쓰지 않는다.
- 작업은 브랜치 → PR. `main` 직접 push 금지.
